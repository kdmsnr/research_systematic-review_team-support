# Protocol for a Qualitative Systematic Review of Support for Development Teams

Version 1.21 · 26 November 2026

## Define the scope and assign responsibilities

Use three questions to guide the review of teams developing products, services, or software in workplaces, practice-based education, and communities.

1. Identify the practices people use to support these teams (RQ1).
2. Identify the outcomes that studies report for the teams, their work, or their members (RQ2).
3. Compare the practices with the outcomes that study authors link to them (RQ3).

Assign screening decisions, source verification, appraisal, coding, and synthesis judgments to the review lead, Masanori Kado. Use AI to prepare candidates under the lead's instructions. Record the model and version when available, the instructions, the input, and the evidence for each candidate. Record the scope and date of human review separately. If a review author is involved in an eligible study, document the involvement, who assessed the study, and the basis for the decision. Have Yuki Taoka and Shigeki Saito review the final results and manuscript in their supervisory roles.

## Identify and deduplicate records

Search the full publication period available from each source through the date of execution. Apply the English metadata filters specified below. Assess the language and publication type of the full report during selection. Do not limit retrieval by year, publication type, subject category, citation count, or open-access status.

### Primary searches

Run each of the four expressions for each source separately. Preserve the exact wording, Boolean grouping, phrase matching, and query membership before combining records. The [eight primary expressions](supplementary-material/search.md#openalex-and-eric) are specified separately for OpenAlex and ERIC.

- **OpenAlex.** Query the works API at `https://api.openalex.org/works` with each [OpenAlex expression](supplementary-material/search.md#openalex-1) in `search.title_and_abstract.exact`. Set `corpus=all`, `filter=language:en`, and `per_page=100`. Request `id,title,doi,publication_year,publication_date,type,authorships,primary_location,referenced_works,language,abstract_inverted_index` using `select`. Start with `cursor=*` and follow each `next_cursor` with the same query and filters until it is null. Retain records on the terminal page. Check the distinct OpenAlex IDs against the query total.
- **ERIC.** Query the public API at `https://api.ies.ed.gov/eric/` with each [ERIC expression](supplementary-material/search.md#eric-1) in `search` across the core fields. Each expression already includes `AND language:English`. Set `format=json`, `start=0`, and `rows=200`. Request `id,title,author,publicationdateyear,source,subject,publicationtype,url,description,language` using `fields`. Advance the offset through all results, retain the empty terminal response, and reconcile distinct ERIC IDs with `numFound`.

### Supplementary searches

- **Google Scholar.** For the review's Google Scholar search, use the SerpApi Google Scholar interface and each of the [eight general expressions, SUP-Q01–SUP-Q08](supplementary-material/search.md#sup-q01). Use the exact phrase as `q`, with `engine=google_scholar`, `hl=en`, `lr=lang_en`, `num=20`, `scisbd=0`, `as_sdt=0`, `as_vis=1`, `as_rr=0`, `filter=1`, and `output=json`. Retrieve the first 200 displayed positions per expression in relevance order, including duplicates, using offsets 0 through 180 in steps of 20. Exclude patents and citation-only entries. Do not add a regional restriction. Stop before the bound only when the end of available results is confirmed. Record short, empty, blocked, or failed pages and any unobserved ranges. Preserve separate ranks and settings for different executions. Use the direct Google Scholar browser interface for any subsequent search, with the same eight general expressions, bounds, English search language, relevance order, and exclusions. Record the controls and positions actually available.
- **Consensus.** Use the connected Consensus search in pro mode with each of the [four Consensus expressions](supplementary-material/search.md#consensus) as a separate query. Take up to the first 20 displayed positions from the initial response in provider order, including duplicate records. Apply no additional filters. Preserve the returned rank, identifier, and source link for each position. Carry these candidates forward with their original discovery dates when updating the other sources.

### Record identification and reuse

1. Reuse saved responses and existing bibliographic records. For each execution, retain the source and interface, exact query and nonsecret settings, date and time zone, source totals and whether they are exact or estimated, raw export hashes, provider IDs, query membership, page or cursor history, errors, and terminal evidence. Retain displayed positions for ranked searches. Keep raw exports containing abstracts private.
2. Preserve candidates from prior knowledge, earlier searches, and citation work under the route by which they were found. Apply the same identity and eligibility rules to them. Do not rerun thesis-specific expressions, pursue further citation tracing, or repeat successful requests to recreate saved evidence. If a search update is undertaken, run the eight primary expressions and the eight general Scholar expressions over the sources' full publication periods.
3. Use exact DOIs, provider IDs, and normalized bibliographic matches to identify possible duplicate reports. Check report identity across the available metadata and versions. Resolve ambiguous matches before merging and record the basis for the decision. An identical title alone is insufficient. Keep separate papers from the same study as separate reports. Preserve each discovery record, query, and date when linking several records to one report.
4. Pass each identified report and its title and abstract variants to abstract retrieval and screening. Reuse the assessment of an unchanged, verified report under the same criteria. Assess a new report or a material change to its title, abstract, identity, language, publication type, or date under the applicable procedure. Record newly indexed older papers with the date on which they were found.

## Screen records and assess reports

### Prepare the screening record

For each distinct report, select the representative title and abstract from the verified records. Preserve the original text variants, discovery routes, and the reason for the choice. Refer conflicting identities or versions to the review lead.

Require a readable abstract that belongs to the identified report. A faithfully reconstructed abstract qualifies. A provider placeholder or search snippet does not. Apply no minimum length. First check saved source exports, raw metadata, and local reference records. If needed, query OpenAlex, Crossref, or DataCite with the available source identifier or DOI. If identifiers do not resolve the abstract, use a bounded exact-title lookup in OpenAlex. Fix the lookup list and result limit for a new round before execution. Reuse successful responses. Save each request, date, result range, response hash, identity check, and disposition. If the bounded procedure yields no usable abstract, record an abstract-availability exclusion. Leave interrupted checks and unresolved matches pending. Reopen the disposition if a matching usable abstract becomes available.

### Apply the eligibility criteria

1. **Publication.** Require an English-language, peer-reviewed journal article available online by the applicable search date. Apply no lower year or open-access limit. Verify the published report's identity and peer-review status, and confirm the full-text language. An accepted manuscript of that article may supply the text. Conference-only reports, theses, book chapters, and standalone preprints fall outside the publication limit.
2. **Empirical study.** Identify qualitative, quantitative, or mixed-methods findings grounded in data with a traceable analysis. A report combining a literature review with original research can qualify on its separable empirical component. Assess practitioner self-study by the same empirical criterion. Theory, advice, or reflection alone cannot.
3. **Development team.** Identify members sharing responsibility for interdependent work to conceive, design, implement, prototype, or evaluate a product, service, or software. One development activity can establish eligibility. Include workplace teams, practice-connected educational projects, and communities when the source establishes that responsibility.
4. **Support in practice.** Identify what someone actually did to support that team's development work, meetings, collaboration, learning, or ways of working. When support forms part of ordinary management, teaching, or a wider organizational initiative, identify the practice directed toward the team. A role title or planned activity alone is insufficient.
5. **Reported consequence.** In the article body, identify the team or participating member, the actual support, and an empirical consequence that the authors link to it. Consider consequences for shared work, development, or a participating member. Favorable, adverse, mixed, and null findings qualify. Intended benefits, disconnected observations, and benefits solely to customers or patients do not meet this criterion. Practitioner noticing, a rationale for choosing support, and evidence of causation are optional.
6. **Methodological basis.** After the first five criteria are met, assess whether the study design, data collection, and analysis support interpretation of at least one reported link. A provisional Yes requires at least one relevant appraised component that supports such an interpretation. Reserve a report-level No for limitations that undermine use of the evidence across the report. Record the component, source location, and reason. An unclear appraisal item, a minor reporting error, or the absence of a control group alone is insufficient. If the original report leaves eligibility unresolved, record Unknown and exclude it from provisional synthesis. An unassessed report has no sixth-criterion judgment. Record component-specific limitations separately.

### Screen titles and abstracts

The review lead supplies the criteria and examples and resolves uncertain cases against the sources. Trial the instructions on varied records before fixing them. The AI first pass assesses criteria 1–4 for every deduplicated record with a usable abstract. Supply the full title, the complete abstract, and traceable publication metadata. Record the model and instructions, input version, proposed disposition, reasons, and supporting words. Route invalid output, ambiguous identity, or conflicting evidence to the lead. A missing detail is Unknown. Forward both potentially eligible and uncertain records for full-text assessment. Propose a clear exclusion only when the input establishes an unmet criterion. Missing abstract information about an outcome cannot settle criterion 5. Preserve the distinction between an AI proposal, its acceptance after sampled checks, and an individual human decision.

### Validate the AI first pass and audit proposed exclusions

The planned checks below govern acceptance of proposed content exclusions. Fix the batch scope, cutoff, sorted record identifiers, input versions, model, configuration, and instructions before processing. Run the checks separately for materially different configurations and for later batches of new or eligibility-relevant changed records.

- **Reference sample.** From the batch of N deduplicated records with usable abstracts, draw a simple random sample of min(100, N) without replacement, using a recorded seed. Include proposed non-journal and non-empirical exclusions in N. The lead records prior exposure and a decision to forward or clearly exclude each record before viewing the AI judgment. Retain the full comparison table and reasons. Every record the lead would forward, including uncertain records, must also be forwarded by the finalized procedure. If the sample contains no human-forward record, leave unassessed proposed exclusions provisional. To accept them, prospectively specify the sampling method, sample size or maximum extent, and acceptance rule or have the lead assess them individually.
- **Exclusion audit.** After reference validation, draw a separate simple random sample of min(100, E) without replacement from the E remaining AI-proposed exclusions the lead has not individually assessed. Record the frame, seed, selected identifiers, and the lead's judgments before disclosing the AI output. Count a potentially eligible or uncertain record as a false exclusion and forward it, even if later excluded at full text. Abstract-availability exclusions are outside both N and E. Check purposeful boundary cases separately.
- **Error handling.** Correct each false exclusion, investigate its cause, and reassess all plausibly affected records. If its reach is unclear, keep the remaining proposed exclusions pending. A change to the instructions or configuration requires reassessing the processed set and fresh random reference validation of the same size where enough unexposed records remain. After remedying any audit false exclusion, draw a fresh audit of min(100, E) from the remaining unassessed exclusions, including when the instructions are unchanged. Keep development cases separate from fresh samples. Accept AI-proposed content exclusions only after the required checks and remedies, with no unresolved false exclusions. If fresh validation or auditing cannot be completed, retain provisional status or record individual human assessments. Report sample results with their denominators.

### Obtain the full text and record the decision

Use a verified full text already held by the review. Otherwise, honor a recorded availability decision or check the title and DOI, where available, through the review's DeepDyve subscription. Record who made the check, its date, report identity, accessible version or restriction, and any ambiguity. A verified lack of access, including a further payment requirement, is Unavailable for this review. An unverified result stays pending. No further public-route search or 14-day repeat is required. Do not contact authors under this procedure. Assess any matching copy obtained later.

The lead makes the source-based eligibility decision. Full-text evidence may update any earlier judgment. Record its location, reason, reviewer, date, and status. For a retrieved report, assign one primary exclusion reason, giving priority to a clear publication, language, or date limit, then the first unmet substantive criterion in order. Leave later unassessed criteria marked as such. Record full-text retrieval failures separately. Report AI processing coverage, unique records individually screened by the lead, sampled checks, and accepted exclusions separately.

## Extract descriptions from the original reports

1. Pilot the extraction form and instructions on reports with different designs. If a field definition changes, recheck affected entries. Treat different papers as separate reports, merge duplicate copies of the same paper, and record known or suspected sample overlap.
2. Work directly from the original English full text. Read the methods, empirical results, and surrounding passages, including relevant tables and figures. For each report meeting the first five criteria, write a description in English for each empirical account in which the authors link an actual support practice to a consequence for the team, its work, or a member. Use separate descriptions when the authors distinguish teams, episodes, or links that can each be traced to their own supporting passages. Keep a program or recurring practice together when the authors report only a shared outcome. Do not split an extracted account during eligibility checks to salvage a better-supported part. Link passages only when the source supports the connection between the people, work, and time in question.
3. Record the setting and team, provider and recipient, support practice, reported outcome, who observed or judged it, and when. Distinguish participant accounts, direct observations, study authors' interpretations, and the review team's interpretation. Record a provider's reasons for offering support only when the source gives them. Retain favorable, adverse, mixed, and null results.
4. For a quantitative result, retain the design, sample and unit of analysis, measure and scale direction, exposure or comparison, timing, estimate, uncertainty, adjustment, and significance threshold where available. Distinguish an explicit report of no change or nonsignificance from an unreported outcome.
5. Give each description a stable identifier linked to its report and PDF hash. For each supporting passage, record its boundaries and physical page, and the section, table, or figure where applicable. Mark quotations, paraphrases, and translations. Have the lead check the original passage in context and record what was checked, by whom, when, and with what decision. Distinguish missing, inapplicable, unclear, and unchecked information.

## Classify practices and outcomes for RQ1 and RQ2

Code support practices and reported outcomes separately in English. Assign more than one code when the source describes distinct practices or outcomes. If the article links support to an eligible team or member outcome, also code consequences for service users or communities where the source reports them. Use constant comparison within and across reports. Group codes that describe similar practices or outcomes, and refine the groups against accounts that differ or fall at a boundary. Combine groups into broader categories where the source material supports the distinction. Record each category’s definition and the passages that illustrate or qualify it. Present a separate coding tree for practices and for outcomes.

Use the same outcome categories across qualitative, quantitative, and mixed-methods reports. For a quantitative example, identify what the study measured and report the design, units, and values needed to interpret it. Preserve the distinction between an association, a change over time, a controlled comparison, and a participant's appraisal. Report quantitative results in their original metrics without pooling estimates or counting the direction or statistical significance of effects.

## Appraise components and select whole descriptions for synthesis

1. Pilot the appraisal instructions and recording form on reports of different designs. For each study, identify its design and the empirical components that support the reported link. Select the appropriate [JBI critical appraisal tool](https://jbi.global/critical-appraisal-tools) for each. For a mixed-methods report, appraise the components by design and assess any limitations in how the authors combined them. Record the tool and version, the scope of each item, its judgment (Yes, No, Unclear, or Not applicable), the reason, and the source location. When only selected items apply, identify those items and their scope. Assess methodological limitations at the study, component, outcome, or result level to which they apply. Use item-level judgments without calculating an overall quality score.
2. State the link the component can support. For a participant's experience, check who described it, how their account was collected and interpreted, and whether it concerns the practice in question. For a reported association, check who or what was measured, the measures, and whether exposure and outcome refer to the same units. For change over time, identify the measurements, groups or participants and time points compared. Use an appraisal of selected items only for the specific result and claim those items cover. Record the item judgments and source passages that matter to that decision.
3. Assign Yes when the source and the relevant appraisal together support the stated interpretation. Limit that interpretation to what the design permits, for example an experience reported by a named participant or a change observed in a single group. Assign No when an identified methodological problem defeats the interpretation. Use Unknown when the source, appraisal, or link between them is insufficient to decide, and specify which is missing. Distinguish an unassessed component from an assessed one whose methods are inadequate.
4. Apply the sixth criterion at report level. Compare the inventory of components with the data sources and analyses in the report. Treat the inventory as complete only when all components are accounted for. If every component in a complete inventory is eligible, the descriptions may pass the component check together. Otherwise trace all practices and outcomes in each whole description to their components and appraisals. Retain it only when eligible components substantiate all of it and the support function is identifiable.
5. When a component link is missing, examine the original passages, assigned codes and relevant appraisals under the same rule whether or not the report already contributes a description. Reuse a verified mapping when the underlying evidence is unchanged. Distinguish a known component of uncertain eligibility from a missing link or an unsupported code. Recount distinct articles and descriptions in each comparison after any change. Record which reports contributed only some of their extracted descriptions and why.

## Comparison of support and outcomes for RQ3

Use each retained description as the unit for comparing support practices with reported outcomes. For each pair of support and outcome categories assigned to the same description, count that description once, even if several codes qualify. A description can contribute to several pairs.

Return to the source passages to establish what the study examined, whose assessment it reported, and how clearly it linked the outcome to the practice. Distinguish an explicit finding of no change or nonsignificance from uncertainty about an outcome that the authors examined. A coded but uncertain outcome identifies a topic the study examined. Leave unreported outcomes out of the counts.

For comparisons between groups, explain how the groups were formed and how overlapping categories were counted. For each comparison, report the number of descriptions and the number of distinct reports, with their respective group denominators. Count a report only once per group and outcome. For exploratory comparisons developed during analysis, report when and why each comparison was chosen, how it was carried out, and how sensitive it was to the coding or eligibility decisions involved.

## Interpret the comparisons and assess confidence

Compare accounts within and across reports in light of the study setting, the source of the evidence, and the timing of the observation or assessment. Interpret counts as patterns in what the included reports documented. When several practices occurred together, attribute a particular outcome to an individual practice only to the extent that the original evidence supports that interpretation.

When examining a finding in more detail, identify how the contributing accounts were selected. Trace each interpretation to its source, examine accounts that qualify or contradict it, and state what remains uncertain. Report the scope of any comparison based on selected accounts.

For each qualitative synthesis finding selected for confidence assessment, apply GRADE-CERQual. Document methodological limitations in the contributing studies, coherence between their accounts and the finding, adequacy of the data, and relevance to the review question. Record the contributing reports, judgments and reasons for each component, and the lead's overall confidence judgment. Identify the finding and evidence covered by each assessment. If the finding changes or new evidence is added, reassess all four components before assigning confidence to the revised finding.

Examine whether interpretations depend on particular reports or overlapping samples, study design, self-study by practitioners, setting, or the distinction between an episode and a recurring practice. Consider missing perspectives, selection and access restrictions, and selective reporting of outcomes. Retain any existing corrections or retraction notices with their lookup scope. Do not initiate further notice checks. State the scope of the checks actually performed and any remaining uncertainty.

## Report and verify the review

Use PRISMA-P for protocol reporting where applicable. Report selection using PRISMA 2020, the searches using PRISMA-S, and the qualitative synthesis using ENTREQ. Apply SWiM to quantitative syntheses of intervention effects where applicable. Show the flow from source records to distinct reports and from reports to eligible descriptions. Identify protocol changes in the manuscript, including their timing relative to extraction and analysis. Record substantial changes to procedures in dated versions.

Generate tables and figures from the review database. Check identifiers, duplicates, original-source locations, and counts at each level. Publish the search methods, included-report characteristics, and scope of the appraisals in the [supplementary material](supplementary-material/). Keep copyrighted full text, private identifiers, and working records out of public files.
